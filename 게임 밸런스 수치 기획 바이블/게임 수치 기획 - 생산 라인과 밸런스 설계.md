### 2.1 게임 장르

**정의**: 게임을 구분하는 분류 방식

**주요 장르:**

**중요성:**

**정의**: 게임의 배경과 스타일을 결정하는 요소

**영향:**

- 유저가 받아들이는 콘텐츠 차별화
- 체험하고 싶은 콘텐츠 결정
- 게임의 분위기와 톤 설정

**예시:**

- 판타지 테마: 마법, 용, 중세 기사
- SF 테마: 우주, 로봇, 미래 기술

### 3.1 속성 설계

**역할**: 게임의 기반

**영향 범위:**

- 전투 시스템
- 육성 시스템
- 전투 로직 형성

**속성 예시:**

```
기본 속성:
- 공격력 (ATK)
- 방어력 (DEF)
- 체력 (HP)
- 속도 (SPD)

상성 속성:
- 불 → 풀 (강함)
- 풀 → 물 (강함)
- 물 → 불 (강함)
```

**설계 고려사항:**

1. 속성 간 상호작용
2. 밸런스 유지
3. 전략적 깊이
4. 직관적 이해도

### 3.2 전투 구조

**역할**: 게임의 커넥터

**기능:**

- 각각의 속성 연결
- 속성과 전투를 연결
- 치밀한 전투 로직 형성

**전투 구조 예시:**

```
1. 턴제 전투
   - 속도 순서대로 행동
   - 스킬 선택
   - 데미지 계산
   - 버프/디버프 적용

2. 실시간 전투
   - 동시 행동
   - 쿨다운 관리
   - 포지셔닝
   - 타이밍 중시
```

**전투 로직 구조:**
````csharp
public class CombatSystem
{
    // 속성 연결
    public float CalculateDamage(Character attacker, Character defender)
    {
        float baseDamage = attacker.ATK - defender.DEF;
        float typeMultiplier = GetTypeMultiplier(attacker.Type, defender.Type);
        float finalDamage = baseDamage * typeMultiplier;
        
        return finalDamage;
    }
    
    // 상성 계산
    float GetTypeMultiplier(ElementType attackType, ElementType defenseType)
    {
        // 불 > 풀: 2배
        if (attackType == ElementType.Fire && defenseType == ElementType.Grass)
            return 2.0f;
        
        // 풀 > 물: 2배
        if (attackType == ElementType.Grass && defenseType == ElementType.Water)
            return 2.0f;
        
        return 1.0f; // 기본
    }
}
````

### 3.3 능력치

**역할**: 게임의 핵심

**중요성:**
> 주인공의 능력치 향상은 게임에서 얻을 수 있는 가장 직접적인 체험 피드백이자 유저가 달성하고자 하는 목표

2. **성장 능력치**: 레벨업에 따른 증가
3. **파생 능력치**: 크리티컬, 회피, 명중
4. **특수 능력치**: 속성 저항, 스킬 강화

**능력치 성장 곡선:**
```
레벨 1: ATK 100
레벨 10: ATK 200
레벨 20: ATK 400
레베 30: ATK 800
...
지수 성장 또는 선형 성장
```

### 3.4 AI 설정

**역할**: 게임의 피드백

**핵심 원칙:**
> 능력치의 향상에는 AI의 당근과 채찍이 필요

**AI의 역할:**
1. **당근**: 성장 동기 부여
   - 적절한 난이도
   - 승리의 쾌감
   - 보상 획득

2. **채찍**: 도전 의식 자극
   - 점진적 난이도 증가
   - 전략적 사고 요구
   - 성장 필요성 인식

**AI 난이도 설계:**
```
초반 (Lv 1-10):
- 적 AI: 단순 공격
- 플레이어 승률: 80-90%
- 목적: 시스템 학습

중반 (Lv 11-30):
- 적 AI: 스킬 사용
- 플레이어 승률: 60-70%
- 목적: 전략 개발

후반 (Lv 31+):
- 적 AI: 고급 전략
- 플레이어 승률: 50-60%
- 목적: 도전과 성취
```

### 4.2 화폐와 자원

**정의**: 게임 경제 시스템에서 상징적인 콘텐츠

**화폐 종류:**
1. **기본 화폐**: 골드, 실버
2. **프리미엄 화폐**: 다이아, 젬
3. **이벤트 화폐**: 기간 한정 재화

**자원 종류:**
1. **육성 자원**: 경험치 포션, 강화석
2. **전투 자원**: 포션, 부활석
3. **제작 자원**: 재료, 레시피

**화폐/자원 설계 예시:**
```
골드 (기본 화폐):
- 획득: 전투, 퀘스트, 판매
- 소비: 강화, 구매, 제작

다이아 (프리미엄 화폐):
- 획득: 과금, 이벤트
- 소비: 가챠, 특별 상품

강화석 (육성 자원):
- 획득: 던전, 상점
- 소비: 장비 강화
```

### 4.3 경제 구조

**역할**: 모든 화폐와 자원의 흐름을 나타냄

**기능:**
- 플레이와 육성 연결
- 자원 순환 구조 형성
- 경제 생태계 유지

**경제 흐름도:**
```
[생산]
전투 → 골드 획득
퀘스트 → 자원 획득
던전 → 강화석 획득

[소비]
골드 → 장비 구매
자원 → 캐릭터 강화
강화석 → 장비 업그레이드

[순환]
강화된 캐릭터 → 더 어려운 전투 → 더 많은 보상
````

**경제 구조 설계:**
````csharp
public class EconomySystem
{
    // 생산 (Production)
    public void EarnGold(int amount)
    {
        playerGold += amount;
    }
    
    // 소비 (Consumption)
    public bool BuyItem(Item item)
    {
        if (playerGold >= item.price)
        {
            playerGold -= item.price;
            AddItemToInventory(item);
            return true;
        }
        return false;
    }
    
    // 순환
    public void CompleteQuest()
    {
        EarnGold(100); // 생산
        // 유저는 이 골드로 다시 소비
    }
}
````

### 4.4 가치 체계

**역할**: 모든 화폐와 자원의 가치 측정

**기능:**
1. 가상 세계에서 가치의 기준 설정
2. 게임의 수익화에 기준이 되는 데이터 지표 제공

**가치 체계 설계:**
```
기준 화폐: 골드 1 = 기본 가치 단위

강화석 1개 = 골드 100
경험치 포션 1개 = 골드 50
일반 장비 = 골드 1,000
희귀 장비 = 골드 10,000

다이아 1개 = 골드 1,000 (과금 가치)
````

**실제 가치 계산:**
````csharp
public class ValueSystem
{
    private const int GOLD_PER_DIAMOND = 1000;
    
    public int ConvertDiamondToGoldValue(int diamonds)
    {
        return diamonds * GOLD_PER_DIAMOND;
    }
    
    public int CalculateItemValue(Item item)
    {
        int baseValue = item.rarity * 1000;
        int levelValue = item.level * 100;
        return baseValue + levelValue;
    }
}
````

### 4.5 경제의 균형

**핵심 원칙:**
> 경제는 생산자와 소비자에 의해 이뤄짐  
> 영원한 생산과 끝없는 소비가 이루어지면 가장 완벽한 경제

**경제 균형 상태:**

| 상태 | 조건 | 결과 | 문제점 |
|------|------|------|--------|
| **디플레이션** | 생산 < 소비 | 화폐/자원 부족 | 성장 정체, 이탈 |
| **균형** | 생산 = 소비 | 안정적 경제 | 이상적 상태 |
| **인플레이션** | 생산 > 소비 | 화폐/자원 과잉 | 가치 하락 |

---

### 디플레이션 (생산 < 소비)

**상황:**
```
플레이어가 얻는 골드 < 필요한 골드
→ 골드 부족
→ 강화 불가
→ 성장 정체
```

**문제점:**
- 성장 속도 저하
- 플레이어 불만 증가
- 게임 이탈 발생

**해결 방법:**
- 보상 증가
- 소비 비용 감소
- 추가 콘텐츠 제공

---

### 인플레이션 (생산 > 소비)

**상황:**
```
플레이어가 얻는 골드 > 필요한 골드
→ 골드 과잉
→ 쓸 곳 없음
→ 화폐 가치 하락
````

**문제점:**

- 성장의 의미 상실
- 도전 의식 저하
- 게임 깊이 감소

**해결 방법:**

- 새로운 소비처 추가
- 고급 콘텐츠 도입
- 자원 소모 증가

---

### 경제 균형 예시
````csharp
public class EconomyBalance
{
    // 일일 생산량
    public int DailyProduction()
    {
        int questReward = 5000;      // 퀘스트
        int battleReward = 3000;     // 전투
        int dailyBonus = 2000;       // 출석
        
        return questReward + battleReward + dailyBonus; // 10,000 골드
    }
    
    // 일일 소비량
    public int DailyConsumption()
    {
        int upgradeCost = 4000;      // 강화
        int shopPurchase = 3000;     // 상점
        int skillUpgrade = 3000;     // 스킬
        
        return upgradeCost + shopPurchase + skillUpgrade; // 10,000 골드
    }
    
    // 균형 체크
    public bool IsBalanced()
    {
        return DailyProduction() == DailyConsumption(); // true: 균형
    }
}
````

## 5. 수치 검증

**검증 범위:**
- 전투 경험

### 5.1 경제 검증

**정의**: 게임의 경제 흐름을 시뮬레이션하는 과정

**검증 내용:**
1. 성장에 필요한 자원 산출
2. 전투 보상 적절성
3. 자원 획득 난이도
4. 경제 균형 상태

**경제 검증 예시:**
```
시나리오: 레벨 1 → 레벨 10 성장

필요 자원:
- 골드: 50,000
- 경험치: 10,000
- 강화석: 20개

예상 플레이 시간: 5일

일일 획득량:
- 골드: 10,000 (총 50,000) ✅
- 경험치: 2,000 (총 10,000) ✅
- 강화석: 4개 (총 20개) ✅

결과: 균형 잡힌 성장 속도
````

**시뮬레이션 코드:**
````csharp
public class EconomyVerification
{
    public void SimulateGrowth(int startLevel, int endLevel)
    {
        int totalGoldNeeded = CalculateGoldNeeded(startLevel, endLevel);
        int dailyGoldEarned = CalculateDailyGold();
        int daysRequired = totalGoldNeeded / dailyGoldEarned;
        
        Debug.Log($"레벨 {startLevel}에서 {endLevel}까지:");
        Debug.Log($"필요 골드: {totalGoldNeeded}");
        Debug.Log($"일일 획득: {dailyGoldEarned}");
        Debug.Log($"소요 일수: {daysRequired}일");
        
        if (daysRequired > 7)
            Debug.LogWarning("성장 속도가 너무 느립니다!");
    }
}
````

### 5.2 육성 검증

**정의**: 게임의 성장을 시뮬레이션하는 과정

**검증 내용:**
1. 성장 경험의 원활함
2. 핵심 전투에 필요한 데이터
3. 레벨 구간별 성장 속도
4. 육성 시스템 간 밸런스

**육성 검증 예시:**
```
캐릭터 육성 시뮬레이션:

Lv 1 → Lv 10 (초반):
- 소요 시간: 2일
- 체감: 빠른 성장, 만족스러움
- 결과: ✅ 적절

Lv 10 → Lv 20 (중반):
- 소요 시간: 5일
- 체감: 보통 성장, 도전적
- 결과: ✅ 적절

Lv 20 → Lv 30 (후반):
- 소요 시간: 10일
- 체감: 느린 성장, 인내 필요
- 결과: ✅ 적절 (엔드 콘텐츠)
````

**육성 곡선 설계:**
````csharp
public class GrowthVerification
{
    public void VerifyGrowthCurve()
    {
        for (int level = 1; level <= 30; level++)
        {
            int expNeeded = CalculateExpForLevel(level);
            int expPerDay = 1000;
            float daysNeeded = (float)expNeeded / expPerDay;
            
            Debug.Log($"Lv {level}: {daysNeeded:F1}일 소요");
            
            // 성장 속도 체크
            if (level <= 10 && daysNeeded > 1.0f)
                Debug.LogWarning("초반 성장이 너무 느립니다!");
            
            if (level > 20 && daysNeeded > 3.0f)
                Debug.LogWarning("후반 성장이 너무 느립니다!");
        }
    }
    
    int CalculateExpForLevel(int level)
    {
        // 지수 성장
        return (int)(100 * Mathf.Pow(1.5f, level - 1));
    }
}
````

### 5.3 전투 검증

**정의**: 게임의 전투를 시뮬레이션하는 과정

**검증 내용:**
1. 전투 결과의 밸런스
2. 게임 성장에 피드백 제공
3. 난이도 곡선
4. 승률 분석

**전투 검증 예시:**
```
전투 시뮬레이션 (플레이어 Lv 10):

적 Lv 8:
- 승률: 95%
- 체감: 너무 쉬움
- 결과: ⚠️ 보상 낮춤

적 Lv 10:
- 승률: 70%
- 체감: 적절한 도전
- 결과: ✅ 표준 보상

적 Lv 12:
- 승률: 30%
- 체감: 매우 어려움
- 결과: ✅ 높은 보상, 선택적 도전
````

**전투 시뮬레이션 코드:**
````csharp
public class CombatVerification
{
    public void SimulateCombat(Character player, Character enemy)
    {
        int wins = 0;
        int battles = 1000;
        
        for (int i = 0; i < battles; i++)
        {
            if (RunCombatSimulation(player, enemy))
                wins++;
        }
        
        float winRate = (float)wins / battles * 100;
        
        Debug.Log($"승률: {winRate:F1}%");
        
        if (winRate > 80)
            Debug.Log("난이도가 너무 낮습니다");
        else if (winRate < 40)
            Debug.Log("난이도가 너무 높습니다");
        else
            Debug.Log("적절한 난이도입니다");
    }
    
    bool RunCombatSimulation(Character player, Character enemy)
    {
        float playerHP = player.maxHP;
        float enemyHP = enemy.maxHP;
        
        while (playerHP > 0 && enemyHP > 0)
        {
            // 플레이어 공격
            enemyHP -= player.ATK - enemy.DEF;
            
            if (enemyHP <= 0)
                return true; // 승리
            
            // 적 공격
            playerHP -= enemy.ATK - player.DEF;
        }
        
        return false; // 패배
    }
}
````

### 6.1 수익화 포지셔닝

**역할**: 게임의 매출 규모 결정

#### 1. 저과금 모델

```
- 선택적 과금
- 무과금도 즐길 수 있음

타겟: 일반 유저
예시: 대부분의 모바일 RPG
```

#### 3. 고과금 모델
```
특징:
- 높은 과금 천장
- 강력한 과금 유인
- VIP 시스템

타겟: 헤비 유저, 고래
````

````csharp
public class GrowthPackage

    {

        // 골드 환산
        if (contents.ContainsKey(Resource.Gold))
        {
            int goldAmount = contents[Resource.Gold];
            int dailyGoldEarn = 10000;
            daysWorth += goldAmount / dailyGoldEarn;
        }
        
        // 경험치 환산
        if (contents.ContainsKey(Resource.Exp))
        {
            int expAmount = contents[Resource.Exp];
````

### 수익화 검증 코드
```csharp
public class MonetizationVerification
{
    public void SimulateUserSpending(UserType userType, int days)
    {
        int totalSpent = 0;
        int currentLevel = 1;
        int currentPower = 1000;
        
        for (int day = 1; day <= days; day++)
        {
            // 일일 무료 진행
            currentLevel += GetDailyLevelGain(userType);
            currentPower += GetDailyPowerGain(userType);
            
            // 과금 시뮬레이션
            int dailySpending = GetDailySpending(userType, day);
            totalSpent += dailySpending;
            
            // 과금 효과 적용
            if (dailySpending > 0)
            {
                currentLevel += GetSpendingLevelBonus(dailySpending);
                currentPower += GetSpendingPowerBonus(dailySpending);
            }
            
            // 주간 리포트
            if (day % 7 == 0)
            {
                Debug.Log($"[{userType}] Day {day}:");
                Debug.Log($"  Level: {currentLevel}");
                Debug.Log($"  Power: {currentPower}");
                Debug.Log($"  Total Spent: {totalSpent}원");
                Debug.Log($"  Satisfaction: {CalculateSatisfaction(userType, currentLevel, currentPower)}%");
            }
        }
        
        // 최종 리포트

        Debug.Log($"유저 타입: {userType}");
        Debug.Log($"최종 레벨: {currentLevel}");
        Debug.Log($"최종 전투력: {currentPower}");
        Debug.Log($"총 과금액: {totalSpent}원");
        Debug.Log($"LTV (평생 가치): {EstimateLTV(userType, totalSpent)}원");
    }
    
    int GetDailySpending(UserType userType, int day)
    {
        switch (userType)
        {
            case UserType.F2P:
                return 0;
            
            case UserType.Minnow:
                return Random.Range(1000, 3000); // 일 1-3천원
            
            case UserType.Dolphin:
                return Random.Range(5000, 15000); // 일 5-15천원
            
            case UserType.Whale:
                return Random.Range(20000, 50000); // 일 2-5만원
            
            default:
                return 0;
        }
    }
    
    int EstimateLTV(UserType userType, int currentSpent)
    {
        float multiplier = 1.0f;
        
        // 유저 타입별 예상 라이프타임
        switch (userType)
        {
            case UserType.F2P:
                multiplier = 0; // 무과금
                break;
            case UserType.Minnow:
                multiplier = 3.0f; // 약 3개월
                break;
            case UserType.Dolphin:
                multiplier = 6.0f; // 약 6개월
                break;
            case UserType.Whale:
                multiplier = 12.0f; // 약 1년
                break;
        }
        
        return (int)(currentSpent * multiplier);
    }
}
```

## 💡 핵심 포인트

1. **생산 라인**: 준비 → 전투 → 경제 → 검증 → 수익화 순서
2. **준비 작업**: 장르, 테마, 3요소, 타깃 제품으로 방향성 설정
3. **전투 수치**: 속성 → 구조 → 능력치 → AI 순서로 설계
4. **경제 균형**: 생산 = 소비가 이상적, 인플레/디플레 방지
5. **수치 검증**: 경제, 육성, 전투를 시뮬레이션으로 검증
6. **수익화**: 포지셔닝 → 전략 → 검증으로 최적화
7. **유저 경험**: 모든 설계의 최종 목표
8. **데이터 기반**: 추측이 아닌 검증된 수치로 결정
9. **밸런스**: 모든 요소 간의 균형이 게임의 수준 결정
10. **지속 가능성**: 장기적 관점의 설계 필요
