### 🎯 핵심 개념

- **Singleton Pattern 정의:**  
    특정 클래스의 인스턴스를 하나만 유지하고, 어디서든 접근할 수 있도록 하는 디자인 패턴.

- **목표:**
- 전역적으로 접근 가능한 단일 객체 제공
- 중복 인스턴스 생성을 방지

- **특징:**
- `static` 변수를 통해 인스턴스 관리
- 전역 접근 가능하지만, 남용 시 의존성이 커질 수 있음

---

### 🛠️ 구현 방식

1. **Singleton 클래스 작성**
- `private static` 인스턴스 변수 선언
- `public static Instance` 프로퍼티로 접근 제공

2. **생성자 제한**
- `private` 생성자를 사용해 외부에서 직접 생성 불가

3. **Unity 적용**
- `Awake()`에서 인스턴스 초기화
- 중복 인스턴스 발생 시 제거

---

### 🎮 Unity 활용 예시

- **게임 매니저(GameManager):**
- 게임 진행 상태 관리

- **UI 매니저(UIManager):**
- 전역적으로 UI 제어

- **사운드 매니저(SoundManager):**
- 배경음악 및 효과음 관리

---

### ✅ 장점

- 전역 접근 가능 → 편리한 참조
- 인스턴스 중복 방지
- 관리가 단순해짐

---

### ⚠️ 주의점

- 남용 시 코드 의존성이 심해질 수 있음
- 테스트 및 확장성에 제약 발생 가능
- 멀티스레드 환경에서는 동기화 처리 필요

---

### 📚 결론

- **Singleton Pattern은 전역적으로 하나의 인스턴스를 제공하는 핵심 디자인 패턴**
- Unity에서 게임 매니저, UI 매니저, 사운드 매니저 등 관리 객체에 적합
- 단, 남용을 피하고 필요한 경우에만 사용하는 것이 바람직
