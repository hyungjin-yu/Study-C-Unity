### 🎯 핵심 개념

- **Command Pattern 정의:**  
    요청(명령)을 객체로 캡슐화하여 호출자와 수신자를 분리하는 디자인 패턴.

- **목표:**
- 실행할 동작을 객체로 만들어 관리
- 요청을 큐에 저장하거나, 실행 취소(Undo) 기능을 구현 가능

- **특징:**
- 호출자(Invoker)와 수신자(Receiver)를 분리
- 명령을 객체로 관리 → 재사용성과 확장성 강화

---

### 🛠️ 구현 방식

1. **Command 인터페이스 정의**
- `Execute()` 메서드 선언
- 필요 시 `Undo()` 메서드 추가

2. **Concrete Command 클래스 구현**
- 특정 동작을 캡슐화한 클래스 작성
- 예: `MoveCommand`, `AttackCommand`, `JumpCommand`

3. **Invoker(호출자)**
- 명령을 실행하거나 큐에 저장
- 실행 취소 기능을 제공할 수 있음

4. **Receiver(수신자)**
- 실제 동작을 수행하는 객체

---

### 🎮 Unity 활용 예시

- **플레이어 입력 처리:**
- 키 입력 → Command 객체로 변환 → 실행

- **Undo/Redo 시스템:**
- Command 객체를 스택에 저장 → 실행 취소 가능

- **AI 행동 관리:**
- 명령 큐를 통해 순차적으로 행동 실행

---

## ✅ 장점

- 요청을 객체로 관리 → 재사용성 강화
- Undo/Redo 기능 구현 용이
- 호출자와 수신자 분리 → 코드 유연성 확보
- 명령을 큐에 저장하여 순차 실행 가능

---

### ⚠️ 주의점

- 명령 객체가 많아지면 관리가 복잡해질 수 있음
- 단순한 로직에는 오히려 과도한 구조가 될 수 있음

---

### 📚 결론

- **Command Pattern은 요청을 객체로 캡슐화하여 유연한 실행 관리가 가능한 핵심 디자인 패턴**
- Unity에서 입력 처리, AI 행동, Undo/Redo 시스템 등 다양한 상황에 적용 가능
- 코드 확장성과 유지보수성을 높이는 데 유용
