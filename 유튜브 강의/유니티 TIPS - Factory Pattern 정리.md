### 🎯 핵심 개념

- **Factory Pattern 정의:**  
    객체 생성을 별도의 팩토리 클래스로 위임하여, 코드에서 직접 `new`를 사용하지 않고 생성 과정을 캡슐화하는 디자인 패턴.

- **목표:**
- 객체 생성 로직을 한 곳에서 관리
- 코드 중복 감소 및 유지보수성 향상

- **특징:**
- 생성 과정과 사용을 분리
- 다양한 타입의 객체를 유연하게 생성 가능

---

### 🛠️ 구현 방식

1. **Factory 클래스 작성**
- 특정 객체를 반환하는 메서드 정의 (`CreateEnemy()`, `CreateItem()` 등).

2. **객체 생성 로직 캡슐화**
- 내부에서 `new`를 사용하지만 외부에서는 Factory 메서드만 호출.

3. **Unity 적용**
- Prefab을 활용해 다양한 오브젝트를 생성.
- ScriptableObject와 결합해 데이터 기반 생성 가능.

---

### 🎮 Unity 활용 예시

- **적(Enemy) 생성:**
- Factory에서 적 타입을 받아 해당 Prefab을 인스턴스화.

- **아이템(Item) 생성:**
- 무기, 포션 등 다양한 아이템을 Factory 메서드로 관리.

- **UI 요소 생성:**
- 팝업, 버튼 등을 Factory로 일관성 있게 생성.

---

### ✅ 장점

- 객체 생성 로직을 중앙 집중화 → 관리 용이
- 코드 중복 감소
- 새로운 타입 추가 시 기존 코드 영향 최소화
- 테스트 및 확장성 강화

---

### ⚠️ 주의점

- 단순한 프로젝트에서는 오히려 구조가 과도해질 수 있음
- Factory 클래스가 지나치게 커지면 관리가 어려워질 수 있음

---

### 📚 결론

- **Factory Pattern은 객체 생성 로직을 캡슐화하여 유지보수성과 확장성을 높이는 핵심 디자인 패턴**
- Unity에서 적, 아이템, UI 등 다양한 오브젝트 생성에 활용 가능
- 코드 품질과 협업 효율성을 개선하는 데 유용
