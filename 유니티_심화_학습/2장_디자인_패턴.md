# Chapter 2: 유니티 핵심 디자인 패턴

디자인 패턴은 "자주 발생하는 문제들에 대한 재사용 가능한 해결책"입니다. 유니티 개발에서 가장 필수적인 패턴 3가지를 집중적으로 살펴봅니다.

---

## 1. Singleton (싱글톤) 패턴

**목적**: 클래스의 인스턴스를 단 하나만 존재하게 하고, 어디서든 접근 가능하게 합니다.
**활용**: `GameManager`, `SoundManager`, `DataManager` 등 전역 시스템 관리.

### 제네릭 싱글톤 구현 (추천 방식)
매번 싱글톤 코드를 작성할 필요 없이 상속만으로 사용 가능한 구조입니다.

```csharp
using UnityEngine;

public class Singleton<T> : MonoBehaviour where T : MonoBehaviour {
    private static T _instance;

    public static T Instance {
        get {
            if (_instance == null) {
                _instance = FindObjectOfType<T>();
                if (_instance == null) {
                    GameObject go = new GameObject(typeof(T).Name);
                    _instance = go.AddComponent<T>();
                }
            }
            return _instance;
        }
    }

    protected virtual void Awake() {
        if (_instance == null) {
            _instance = this as T;
            DontDestroyOnLoad(gameObject);
        } else {
            Destroy(gameObject);
        }
    }
}

// 사용 예시
public class GameManager : Singleton<GameManager> {
    public int score = 0;
    public void AddScore(int s) => score += s;
}
```

## 2. Observer (옵저버) 패턴

**목적**: 객체의 상태 변화를 관찰하고, 변화가 생길 때마다 관련된 객체들에게 통지합니다. 클래스 간의 결합도(Dependency)를 획기적으로 낮춰줍니다.
**활용**: 체력 변화에 따른 UI 업데이트, 퀘스트 완료 알림.

### C# Action을 활용한 이벤트 시스템
```csharp
using System;
using UnityEngine;

public class PlayerHealth : MonoBehaviour {
    public int maxHealth = 100;
    private int currentHealth;

    // 옵저버들이 구독할 이벤트 (int는 현재 체력)
    public static event Action<int> OnHealthChanged;

    void Start() {
        currentHealth = maxHealth;
    }

    public void TakeDamage(int damage) {
        currentHealth -= damage;
        // 이벤트 발생 (구독자가 있을 때만 호출)
        OnHealthChanged?.Invoke(currentHealth);
    }
}

// UI 클래스 (PlayerHealth를 직접 참조할 필요 없음!)
public class HealthUI : MonoBehaviour {
    void OnEnable() {
        PlayerHealth.OnHealthChanged += UpdateHealthUI; // 구독
    }

    void OnDisable() {
        PlayerHealth.OnHealthChanged -= UpdateHealthUI; // 해제 (필수)
    }

    void UpdateHealthUI(int health) {
        Debug.Log($"UI 업데이트: 현재 체력은 {health}");
    }
}
```

## 3. State (상태) 패턴

**목적**: 객체의 내부 상태에 따라 동작을 변경할 수 있게 합니다. 복잡한 `if-else` 또는 `switch` 문을 방지합니다.
**활용**: 플레이어 상태(Idle, Move, Attack, Jump), 적 AI.

### 인터페이스 기반 상태 패턴 예시
```csharp
public interface IState {
    void Enter();
    void Execute();
    void Exit();
}

public class IdleState : IState {
    public void Enter() => Debug.Log("대기 상태 진입");
    public void Execute() { /* 대기 로직 */ }
    public void Exit() => Debug.Log("대기 상태 퇴장");
}

public class StateMachine {
    private IState currentState;

    public void ChangeState(IState newState) {
        currentState?.Exit();
        currentState = newState;
        currentState.Enter();
    }

    public void Update() => currentState?.Execute();
}
```

## 💡 요약 및 팁
- **싱글톤**은 편하지만 남용하면 코드 간의 의존성이 너무 강해집니다. 전역 관리가 정말 필요한 경우에만 사용하세요.
- **옵저버 패턴**은 유니티 개발의 꽃입니다. 클래스 A가 클래스 B를 몰라도 소통할 수 있게 하여 코드 유지보수성을 극대화합니다.
- **Action** 사용 시 반드시 `OnDisable`에서 구독을 해제(`-=`)해야 메모리 누수를 방지할 수 있습니다.
